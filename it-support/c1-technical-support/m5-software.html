Know this — the need-to-know core, 7 facts
Software
instructions plus data. Compiled languages (C, C++, Go) become a machine-code binary; interpreted ones (Python, JavaScript) are run by an interpreter.
Installer
delivers the files, registers the app with the OS, writes its configuration, and creates shortcuts and uninstall entries.
Windows
MSI or EXE installers; winget and Chocolatey for command-line installs; Settings or Programs and Features to remove.
Linux
package managers install from signed repositories and resolve dependencies: apt on Debian/Ubuntu, dnf on Fedora/RHEL. Never mix managers for one package.
Why update
most attacks use a vulnerability that already has a patch. Patching is the highest-value routine task in the job.
Scripting
a text file of commands run in order (PowerShell .ps1, Bash .sh). Automate anything you would otherwise do twice.
Licensing
per seat, per device, subscription, or open source. The licence decides how many machines may run it, which is an audit question, not a moral one.
The trap: Assuming a reinstall fixes a fault. Reinstalling over the same leftover configuration reproduces the same problem - remove the app's data too, or you learn nothing.

What software is, and how it gets built

Text a human wrote, turned into instructions a CPU can execute. There are only two ways to make that trip.

Source code is the program as written — in Python, C, JavaScript, Java. The CPU cannot execute it. It has to be translated, and the two translations behave very differently:

CompiledInterpreted
HowA compiler translates the whole program ahead of time into a native executable.An interpreter reads and executes it line by line, every run.
ResultOne binary for one platform — .exe, .dll, an ELF binary.A script that runs anywhere the interpreter is installed — .py, .js, .sh.
SpeedFast: no translation at run time.Slower, though modern engines compile the hot parts as they go.
PortabilityRebuild per platform.Usually none needed.
You can read it?No. The binary is machine code.Yes — which is why scripts are how people automate things.
Bytecode
The middle path: compiled once into an intermediate form, then run by a runtime. Java's .class, .NET's IL, Python's .pyc. Write once, run where the runtime exists.
Library
Code somebody else already wrote, that your program calls instead of reimplementing. A dependency.
SDK
The tools for building against a platform: compiler, libraries, headers, documentation.
Script
A short program written to automate a task, usually interpreted, usually read by a human later — possibly you.

The three kinds of software you support

Firmware, system software, application software. Every ticket is about one of them, and they fail differently.

KindExamplesHow it fails
FirmwareBIOS/UEFI, a drive's controller firmware, a printer's firmwareRarely, and badly. A failed firmware update can brick the device; that is why it is done with a UPS connected.
System softwareThe operating system, drivers, services, the runtimeWide: everything above it stops working. Boot failures, blue screens, "nothing opens".
Application softwareA browser, Office, a game, a line-of-business appNarrow: one program misbehaves while the machine is fine.

The first diagnostic question on any software ticket is therefore which kind. If one application is broken, you fix the application. If everything is broken, you are looking at system software — and if the machine will not start at all, firmware or boot.

Utility software sits between the last two: disk cleanup, backup agents, antivirus, compression tools. They are applications, but they touch system-level things, which is why they need elevated permissions and why a bad antivirus update can take a whole fleet down at once.

The format tells you the platform, the risk, and whether uninstalling will actually remove it.

Two rules that prevent most malware

Download from the source
The vendor's own site, or the OS's app store. "Free download" mirrors wrap installers with adware and worse. If a search result offers a "faster download", close it.
Check the signature
Windows shows "Unknown publisher" in the UAC prompt; macOS refuses unsigned apps by default (Gatekeeper); Linux verifies repository signatures. A warning about an unsigned installer is information, not friction.

Permissions: installing writes to system locations, so it needs administrator rights. That elevation prompt is the last checkpoint where you can still say no — which is exactly why malware wants you to click it.

What a package manager actually does

  • Reads the repository: a signed catalogue of available software and versions.
  • Works out the dependencies — the libraries the program needs — and installs them too.
  • Verifies the signature so a tampered package is refused.
  • Records what it did, so removal is complete rather than "delete the folder and hope".
update refreshes the catalogue (what versions exist). upgrade actually installs the newer versions. On apt that is two commands, and running only the first is a very common mistake: the machine reports it is up to date because it is reading a stale list.

Updating, and uninstalling properly

The part of software management that is actually a security control.

An update (or patch) fixes bugs, closes vulnerabilities, and sometimes adds features. Most successful attacks use a vulnerability that already has a patch — the victim simply had not installed it. The window between a patch being published and a machine being patched is the entire opportunity.

Automatic updates
The highest-value setting on any machine you support. Turn them on unless something specific forbids it, and say why when it does.
Reboot required
A patch that replaces a running file only takes effect after a restart. "It says updated but nothing changed" usually means the reboot never happened.
End of life
When a vendor stops supporting a version, it stops shipping patches. An unsupported OS is not old, it is unsafe — that is the whole argument for upgrading.
Version number
Major.minor.patch. A major change can break compatibility; a patch should not. Read which one you are agreeing to.
Rollback
Snapshots, restore points, or the previous package version. Know how to undo before you update, especially on a machine you cannot easily reach.

Uninstalling

Use the platform's own removal path — Settings → Apps on Windows, the package manager on Linux, dragging to the Bin and emptying it on macOS. Deleting the folder leaves the registry entries, services, scheduled tasks and user data behind, which is how a "removed" program keeps running at startup.

Leftovers worth knowing: Windows keeps %APPDATA% and %PROGRAMDATA% user and machine data; Linux leaves ~/.config and ~/.local; macOS leaves ~/Library/Application Support. They are also the first thing to clear when an application misbehaves after a reinstall.

Compatibility, licensing, and the questions before you install

Five things to check, in the order that saves the most time.

  1. Does the OS support it? The version matters, not just the name — a program written for Windows 7 may refuse Windows 11, and macOS drops support for old applications on a schedule.
  2. 32-bit or 64-bit? Almost everything is 64-bit now, and a 32-bit application still runs on a 64-bit OS (not the reverse). This is where "the installer will not run" comes from.
  3. Hardware requirements — RAM, disk space, and for anything graphical, the GPU. Check before the download, not after the failure.
  4. Licence. Per-seat, per-device, subscription or site licence — installing one copy on ten machines is a compliance problem, not a technical one, and it is the support technician who gets asked to prove it.
  5. Do you have the rights? Installing needs administrator permission. On a managed machine that is a policy decision, not a technical obstacle to work around.
The one that bites in real life: the newest version is not automatically the right one. A line-of-business application that requires an older runtime will break when something updates that runtime underneath it. On managed machines, version pinning is a deliberate choice, not laziness.
