The essentials — hold these before the detail

The module at entry-certification level: what you must be able to do, and the facts the quizzes and drills on this page are testing. Read this first, every time.

You can — by the end of this module
  • name the five layers and say what each one is responsible for
  • explain encapsulation and name the data unit at each layer
  • describe how a hub and a switch move data differently
  • explain what a MAC address is and how a switch learns where to send frames
  • tell the TCP/IP model from the OSI model
Know this — the need-to-know core, 7 facts
Five layers
physical, data link, network, transport, application. Each one solves a problem the layer below cannot.
Encapsulation
each layer wraps what it was given and adds its own header: data, then a TCP segment, then an IP packet, then an Ethernet frame, then bits. The receiver strips them in reverse.
Media
twisted pair with RJ45 (about 100 m), fibre for distance and speed, coax. The distance limit is why you need switches and repeaters.
Hub vs switch
a hub repeats everything to every port, so everyone shares one collision domain. A switch forwards only to the port the destination MAC is on.
MAC address
48 bits, written as six hex pairs; the first three bytes identify the manufacturer. It is local to one network.
Ethernet frame
destination MAC, source MAC, type, payload, and a frame check sequence for corruption.
OSI versus TCP/IP
OSI has seven layers (it splits application into application, presentation and session); TCP/IP has five. Learn the five, recognise the seven.
The trap: Thinking a MAC address travels end to end. The frame's MAC header is thrown away and rebuilt at every hop; only the IP packet survives the journey.

Everything below this box explains these lines, in this order, with a drill after each part that tests it. If you can say every line above without looking, the drills are revision. If you cannot, read the section that matches the line and come back — that is the whole study method. The same objectives for every module, built and not yet built, are on the learning path.

What this module is really about

Not “learn the diagram”. It is: every network problem sits in one layer, and once you can name the layer you can name the fix.

You have a working computer talking to another computer somewhere else. That took five separate jobs, invented by five different groups of people, and the model is simply the list of those jobs in the order they happen. Nothing more. Once you can walk a packet down the stack and back up again, every question in this module answers itself.

The sentence the rest of Course 2 is built on: IP addresses are end-to-end and survive the whole trip. MAC addresses are hop-to-hop and are rewritten at every router. Ports are process-to-process on the two end machines.

Why bother with a model at all

Two reasons, and both are job reasons:

A shared vocabulary
A vendor's datasheet, a textbook, and the person at the ISP all describe the same journey with the same five words. “Layer one problem” is a complete sentence between technicians.
A fault-isolating trick
One job per layer means you can rule out a whole layer at a time instead of guessing. Link light on? — that one question discards the bottom layer and everything above it instantly.

Encapsulation — who wraps what, and what survives a hop

Sending wraps top → bottom. Receiving unwraps bottom → top. The data itself never changes.

Each layer takes whatever the layer above handed it, puts its own header in front, and passes the result down. The header is how that layer talks to its copy on the other machine — the two transport layers are conversing about ports, the two network layers about addresses, and nothing in between understands any of it.

Build the wrap

Add the next layer's step. Then use Decapsulate to walk it back off.

Guaranteed quiz question. At a router hop, the data-link header is stripped and rebuilt for the next local network. The network header is never touched — it is end-to-end. That is why a traceroute shows you every router along the path while the destination IP stays fixed the whole way.

The words that get swapped on people

Encapsulation
Adding headers on the way down the sender's stack.
Decapsulation
Stripping headers on the way up the receiver's stack.
Segmentation
A transport-layer job: cutting a large message into segments that fit. Not the same as wrapping, and the exam keeps offering it as a distractor.
Encrypted
Nothing to do with layers. Wrapping is not hiding — TLS does the hiding, and it does it inside the payload.

Five layers or seven — TCP/IP against OSI

This course teaches the five-layer model. The OSI model has seven and splits the top one three ways.

You will meet both. They are not rivals; OSI is the older, more detailed map and TCP/IP is the one that describes what actually runs. The only difference in content is that OSI breaks the application layer into three, so the bottom four are the same idea with different numbers. Learn five, recognise seven, and never answer “seven” when the question says “the TCP/IP model”.

Name the stack, top to bottom

Top of the stack is closest to the application — its data is created first. Bottom is closest to the wire — it goes out last.

OSI is the ISO reference model; the five-layer model taught in this course is the TCP/IP-inspired teaching model. Both appear in A+ objectives, so the number itself is a fact worth memorising.

The physical layer — signals, media, and what actually breaks

The only layer you can stub a toe on. It converts bits into signals and moves them across a medium.

Electrical pulses on copper, light pulses in fibre, radio waves in the air. Same zeros and ones, different carrier. It covers the signal, the hardware that makes the signal (NIC electronics, modems, hubs, radios) and the medium that carries it.

Three media, four things to know about each: how fast, how far, what kills it, and what the connector is called. That is the whole physical-layer syllabus.

Exam trap: a router, a switch and a gateway are all hardware you can hold, but none of them are physical-layer devices. Their work is at L3 (IP) and L2 (MAC). “It's a box” is not a layer — the layer is the job. A home “router” is five small roles stacked in one case: an L1 modem, an L2 switch, an L3 router, NAT, and an L1/L2 Wi-Fi radio.

The data link layer — the local hop

Four jobs: frame it, address it with MAC, check it for damage, control access to the medium. Its device is the switch.

A packet has an IP address that says where the destination is in the whole internet. This layer does not care about that. It answers a smaller, dumber, more useful question: how do I get this frame onto the wire and to the device on the other end of this link?

The two ideas that make this layer click

Why a switch beats a hub
A hub repeats every frame out of every other port: one shared collision domain, everyone waits their turn, everyone hears everyone. A switch forwards a frame only out of the port the destination MAC was learned on, so each port is its own collision domain. That is the entire performance difference, and it is also a privacy difference.
How a switch learns
It reads the source MAC of every frame and records “that MAC lives on this port”. Unknown destination MAC → flood out every port except the one it arrived on, then remember the answer. The table ages out, or a moved machine would be unreachable forever. mac-address-table (Cisco) or the vendor's equivalent is where you look.
Wi-Fi is data link too
802.11 is Ethernet's wireless cousin: same jobs — frame, address, check, medium access — but it can't hear while it talks, so it uses CSMA/CA (collision avoidance, listen before you send) instead of Ethernet's collision detection. SSIDs and associations are also this layer.

ARP is the bridge between this layer and the network layer — “I know the IP, what's the MAC?” — and it gets its own full treatment in Module 2. What matters here is only this: the IP address names the destination, the MAC address names the courier for this hop.

Learn the layer each device works at and identification becomes almost automatic: hubs touch signals, switches touch MACs, routers touch IPs.

Which layer does this live at?

Signals, MACs, or IPs. Anything that straddles two layers goes where its deciding work happens.

“Gateway”, “firewall” and “controller” are roles, not boxes — a single device can fill several, and helpdesk answers that name a role instead of a product are the ones that survive follow-up questions.

Troubleshooting upward, the way the course wants it

The helpdesk method this course teaches starts at the physical layer and climbs, because the bottom layer is the cheapest to check and everything above it depends on it: is it plugged in → is the link light on → do I have an address → can I reach my gateway → can I reach the internet by IP → can I reach it by name → does the application work. Each “yes” discards a layer; the first “no” is your suspect. (CompTIA prefers starting from the user's symptom and working down, then back up. Both are defensible; say which you're using and you're right either way.)

Exam traps in this module

Every one of these is a distractor that has been written by someone who has marked your paper.

“A switch regenerates the signal, so it's physical layer”
No. Regenerating a signal is physical, but a switch's deciding work reads MAC addresses — it is a data-link device. Judge a device by the address it reads.
“The FCS retransmits the damaged frame”
Nothing retransmits at L2. Ethernet switches drop a frame whose check fails. Recovery is TCP's job, several layers up — which is exactly why “Ethernet is unreliable, TCP makes it useful” is a fair sentence.
“An IP address belongs to the computer”
It belongs to the network the machine is currently attached to. Same laptop, different building, different address. The MAC is the one that travels with the hardware.
“A hub is a cheap switch”
Different layer's worth of intelligence: a hub has none — it repeats bits out of every port, so everyone shares one collision domain and one bandwidth pool.
“The OSI model has five layers” / “TCP/IP has seven”
OSI seven, TCP/IP five as taught here. The three OSI layers that vanish are presentation and session, folded into application.
“The router changes the destination IP as the packet crosses it”
It rewrites the MAC header for the next hop and decrements TTL. Destination IP stays put — except under NAT, which is a deliberate, separate translation, not ordinary forwarding.
“Wi-Fi is a different model”
Same layer, different mechanism. 802.11 is data link, with collision avoidance instead of detection because a radio can't listen and talk at once.
