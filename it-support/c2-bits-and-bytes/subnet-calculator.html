The subnet calculator

An address and a slash in, the whole method out — asked back to you one checkpoint at a time, with a table that fills in as you go.

What this section gets you. Two numbers — an address and a slash — are the whole input. Out of them the method produces: the subnet mask, how many host bits are left, the block size and the interesting octet, the network address, the broadcast, the first and last usable host, how many devices fit, whether the address you typed can even be given to one, what kind of address space it sits in, and the subnet either side of it. Two of those — the class and the scope — need no method at all: they are readable straight off the first octet. Nothing is looked up; every value is computed from what you type.

Pick an example or type your own, then work down the checkpoints. Each answer adds a row to the table underneath, so you can stop as soon as the row you wanted is there: the dimmed rows name the checkpoint that would earn them, and nothing later in the method changes a fact you already hold. If you would rather see the whole answer printed at once, switch to Show the whole working — the same arithmetic, none of the questions.

Why a network address exists at all

Step 5 prints a number that is on no device. It is not a formality — it is the value the whole system is built on, and this page used to assume you already had it.

An address is two numbers packed into one, and the mask is the ruler that says where the cut is. Take 112.15.167.104/22: the first 22 bits say which network, the last 10 say which host on it. Zero the host bits and what is left is the network address, 112.15.164.0. Read those host bits as a number — 3 × 256 + 104 = 872 — and you have the host's position inside the block. Same 32 bits, two ways of quoting them.

The analogy that holds: 112.15.167.104 is a house number, and 112.15.164.0/22 is the street name — a street with 1,024 lots on it. No device is ever given the street's name, and no routing table can list the 1,022 houses, so both halves of the fact are needed and only one of them fits in a route.

Why it has to exist

  • Routing tables speak only this language. A route that reads 112.15.164.0/22 out this interface is one line covering a thousand addresses. There is no line format that lists a thousand addresses.
  • Every host asks the question constantly. Before it sends anything it ANDs the destination with its own mask: same network means ARP for it on the local wire; different means hand it to the default gateway. That decision is made from the network address, never from another host's address.
  • Everything else is named this way too. A DHCP scope, a firewall rule, an access list, a subnet plan — each is a network address plus a mask, and an individual host address only ever appears inside one.

Why it is never a device's address

All-zero host bits is how an address says "the subnet itself". Give a machine 112.15.164.0 and "the network" and "a host on the network" become the same bits, so the AND could no longer tell you which one you meant. All-ones has the same problem in the other direction: 112.15.167.255 means every host here, which no single device can be. That is where 2n − 2 comes from — with /31 and /32 as the two documented exceptions further down this page.

Why it feels strange at home: the third octet moves

An ordinary LAN is all /24, so the network address is always x.x.x.0 and the gateway always x.x.x.1 — the pattern never varies and there is nothing to notice. Widen the mask past an octet boundary and the third octet stops being fixed. A /22 is four values wide there, and a block can only start on a multiple of its own size:

NetworkCovers (inclusive)Octet 3What it is

That is the whole reason for 164 and not 167: 167 is a host inside the block that began at 164. It is also why 112.15.161.0/22 does not exist — 161 falls inside the block that began at 160, and a four-wide block cannot start there.

Calculator step 9 draws this for whatever address is typed, marking which octet values are network starts and which are hosts.

How to do it by hand, in the order that works

The calculator is for checking. The exam is for doing it, so the steps are written out here in the order that does not need a second thought.

  1. Turn the prefix into the mask. /22 is 22 ones then zeros: 11111111 11111111 11111100 00000000 = 255.255.252.0. Count in ones, not in octets.
  2. Find the interesting octet — the first one that is not 255. Here it is the third, where the mask reads 252.
  3. Block size = 256 − that mask value. 256 − 252 = 4. Networks start on multiples of 4 in that octet: .0 .4 .8 … .164 .168.
  4. Walk down to the network. The address is 112.15.167.104; the largest multiple of 4 that is not above 167 is 164, so the network is 112.15.164.0. (The bitwise AND is the same step done mechanically.)
  5. The next network starts one block later: 112.15.168.0, so this subnet's broadcast is one before it — 112.15.167.255.
  6. Hosts: host bits = 32 − 22 = 10, so 210 = 1,024 addresses and 1,022 usable. Usable is always the first and last address of the block removed — the network and the broadcast are never assigned to a device. /31 and /32 are the two exceptions to the minus two.
Every number above is the one the calculator prints for 112.15.167.104/22 — the address that was on the board in class on 2026-11-05.

The one question that decides everything

Subnetting is not trivia; it answers a single routing question about every packet a host sends.

A host applies its own mask to its own address and to the destination. Same network number means the destination is on the local wire: ARP for it, send the frame, no router involved. Different network number means the host gives the packet to its default gateway and hopes there is a route on the other side.

So a machine with the wrong mask is not "half working" — it can usually reach its own gateway and nothing else, or reach nothing off-subnet at all, while looking perfectly configured. Two hosts, correct addresses, mismatched masks, and no route: that is the whole shape of a very large share of real tickets.

Use the calculator's step 10 to test any pair. It is the same test a router does, done by hand.

Where this goes wrong

Each of these has cost somebody an evening, in class or on a ticket.

the /12 one

172.16 – 172.31, and nothing else

RFC 1918 private space is 10/8, 172.16.0.0/12 and 192.168/16. The middle one is not "all of 172": a /12 steps the second octet in blocks of 16 starting on a multiple of 16 (0–15, 16–31, 32–47 …), so private runs 16 to 31 and 172.15.x.x and 172.32.x.x are public. Derive it and you cannot forget it.

the minus two

Usable is not the count

2host bits counts addresses. Assignable hosts are two fewer, because the network address and the broadcast address are reserved. Except on a /31 (point-to-point, RFC 3021, both usable) and a /32 (one address).

class is not the mask

The class comes from the first octet; the /n is the mask

Two different axes. 192.168.0.0/16 is Class C space with a /16 on it — 256 classful C networks glued into one supernet. Classful defaults (/8 /16 /24) are a default, not a law, and CIDR has ignored them since the mid-90s. Classes still earn their keep reading a first octet fast and answering exam questions.

not private, not public

The ranges people forget

127.0.0.0/8 loopback, 169.254.0.0/16 link-local (what you get when DHCP fails and you have no APIPA override), 100.64.0.0/10 carrier-grade NAT (RFC 6598 — your ISP's shared space, routable nowhere public, and not RFC 1918 either), 224.0.0.0/4 multicast, 240.0.0.0/4 reserved, and the three documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) that exist so examples like this page never point at somebody's real network.
