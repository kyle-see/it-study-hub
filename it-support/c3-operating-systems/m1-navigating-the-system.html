Navigating the System

The essentials — hold these before the detail

The module at entry-certification level: what you must be able to do, and the facts the quizzes and drills on this page are testing. Read this first, every time.

You can — by the end of this module
  • navigate a filesystem and manage files from PowerShell or Bash
  • use wildcards, pipes and redirection
  • find, read and filter text output
  • tell an absolute path from a relative path
  • do the same task on Windows and on Linux
Know this — the need-to-know core, 7 facts
Paths
absolute starts at the root (C:\ or /); relative starts where you are. `.` is here, `..` is the parent.
Navigation
cd, pwd/Get-Location, ls/dir, mkdir, cp/copy, mv/move, rm/del. The verbs differ, the jobs do not.
Everything is a file
on Linux, devices live in /dev and configuration in /etc. That is why one set of tools can read almost anything.
Pipes
send one command's output into the next: `ps aux | grep ssh`. Redirection writes it to a file: > overwrite, >> append, 2> errors.
Permissions
`ls -l` shows rwx for owner, group and other. Windows uses ACLs with inherited rights instead.
Environment variables
machine-wide settings, and PATH is how the shell finds a command at all.
Self-help
man, --help and Get-Help are the reference you are expected to use rather than memorise.
The trap: Running rm without reading the path. There is no recycle bin and no undo on the command line.

Two ways to drive an operating system

A graphical interface and a command line do the same jobs. The command line is faster, repeatable, and the only option on a machine with no desktop.

Every operating system in this course gives you at least two faces. The GUI — the graphical user interface — is the one with windows and a pointer. The CLI — the command-line interface — is a prompt where you type. On Linux the CLI is called a shell, and the language this course uses to talk to that shell is Bash.

SystemCommand-line interfaces
Windowscmd.exe (Command Prompt) and powershell.exe (PowerShell). Two different shells, and they do not accept identical syntax.
LinuxOne shell for this course: Bash. The prompt shows who you are, the machine, and where you are — cindy@cindy-nyc:~/Documents$.

Two words carry the whole grammar of a command:

Parameter
A value associated with a command — usually what it acts on. In cp mycoolfile.txt ~/Desktop, the file and the destination are parameters.
Flag
An option that changes how the command behaves — -r, -l, -Recurse. Two flags can be written together: ls -la / is the same as ls -l -a /.
Why the shell is worth the effort: a typed command is repeatable and scriptable, and it prints the actual error rather than a dialog box that says something went wrong. On a server there is often no desktop at all, so the shell is not the faster option — it is the only one.

The rest of this module is one page of commands after another. If you want the OS theory underneath — kernel and user space, processes, memory, filesystems, the boot process — that is already written and linked, not repeated here: Course 1, Module 3 — Installing and Using Operating Systems.

Paths: two roots, two separators, one idea

A path is a location. The only question that matters before you run a command is whether the path starts at the root or at you.

A path is the location of a file or a directory. Windows and Linux disagree about almost everything in how they write one, and agree completely about what it means.

WindowsLinux
ExampleC:\Users\cindy\Desktop /home/cindy/Desktop
Top of the treeA drive letter, and each drive letter is its own filesystem with its own root — C:\, D:\, X:\ One root for the whole machine, written /
SeparatorBackslash \ Forward slash /
The root isThe parent directory of everything on that drive The directory everything else stems from; ls / lists what is under it

Absolute and relative

Absolute path
Starts from the main directory, so it means the same thing from anywhere: cd /home/cindy/Documents.
Relative path
Starts from your current directory, so it means something different depending on where you are: cd ../Documents.
. and ..
. is here; .. is the parent directory. cd .. from C:\Users\cindy\Documents lands you in C:\Users\cindy.
~
Your home directory, in both shells. It is a shortcut, not a directory called tilde.

That is the whole skill, and it is worth being pedantic about: the first character of a path tells you which of the two kinds you are holding. A drive letter or a leading slash means absolute. A name, a dot or two dots means relative — and a relative path is only as correct as the directory you happen to be in when you run it.

What lives where

Two short lists that turn a filesystem from a maze into a map. You do not need to memorise every directory — only the ones you will actually open.

Listing the root shows the same handful of names every time. These are the ones the course names, with what the notes say each one holds.

Windows, under C:\What it holds
Program Files / Program Files (x86) Most of the applications and other programs installed on the machine — the two folders are the locations Windows keeps them in.
UsersThe user profile directories — the home directories. This is where a person's documents actually live.
WindowsWhere the operating system itself is installed.
Recycle BinWhere files go instead of being deleted immediately. Hidden from a plain listing; ls -Force shows it.
ProgramDataData programs keep for themselves. Also hidden until ls -Force.
Linux, under /What it holds
/binThe essential binaries — the programs the system needs.
/etcSystem configuration files. When you change how a Linux machine behaves, the change usually lives here.
/homePersonal directories: pictures, documents, and everything a person considers theirs.
/procInformation about the processes running right now.
/usrSoftware installed by users, as opposed to the essential binaries in /bin.
/varLogs, and any file that constantly changes.
Handout correction: the notes print /user, with a description about user-installed software. The directory is /usr — no "e". Do not go looking for a /user on a real machine.

"Everything is a file"

On Linux that sentence is close to literal, and it is why the map above is worth learning. Hardware devices are represented as device files in /dev:

Character device
Transmits data character by character — a keyboard, a mouse. /dev/null is one too: it accepts anything you send it and returns nothing.
Block device
Transfers data in blocks, the unit of storage — hard drives, USB sticks. They appear as /dev/sda, /dev/sdb, and so on, with the letter assigned in the order the machine detected them.
Why it matters
Configuration is text in /etc, logs are text in /var, devices look like files in /dev. The same handful of commands — read, search, copy — works on all of it.

Finding your way: list, print, change

Three commands you will type more than every other command combined, and the two shortcuts that stop you typing them so much.

Two habits turn this from typing into navigating:

Tab completion
Type the first letter of a name and press Tab. In PowerShell it completes the first match, and pressing Tab again rotates through the other options. In Bash it shows you all the options at once. Either way you stop typing long names, and you stop mistyping them.
History
history lists what you have already typed. Ctrl+R searches back through it — in older PowerShell versions, type # and use Tab completion instead.

Aliases: why the same command has two names

In PowerShell, ls and cat are aliases — short names that point at the real command. The alias exists so that muscle memory from Linux and cmd keeps working, and it is why the same word can mean something slightly different in two shells.

Get-Alias
Get-Alias ls answers Get-ChildItem: that is the real cmdlet behind the alias. Run it on any command you are unsure about rather than assuming the Linux meaning carries over.
The support lesson: when a command "does not exist" in PowerShell, it is usually an alias you have not got, a cmdlet you have not spelled, or a tool that is not installed. Get-Alias and Get-Help answer the first two before you go looking for the third.

Making, copying, moving and removing

Create, copy, rename, delete — on both systems, including the wildcard that does it to a hundred files at once.

Make a directory

mkdir foldername works in both shells. A name with spaces in it needs help, because the shell splits arguments on spaces:

Quotes
mkdir "my new file" — works in both shells, and is the version to prefer.
PowerShell
Or escape the space with a backtick: mkdir my` new` file. An escape tells the shell to treat the next character literally instead of as a separator.
Bash
Or escape the space with a backslash: mkdir my\ new\ file.
Handout correction: the notes describe Bash's escape character as (/) — a forward slash. It is the backslash, \. Quote the name and you never have to remember.

Copy

Copy takes what you want to copy, then where you want it. A wildcard is a character that selects files by a pattern — the asterisk means "all":

PowerShellBashResult
cp mycoolfile.txt C:\Users\cindy\Desktop cp my_file.txt ~/Desktop One file, to a new location.
cp *.jpeg C:\Users\cindy\Desktop cp *.png ~/Desktop Every file of that type in the current directory.
cp "Bird Pictures" C:\Users\Cindy\Desktop -Recurse -Verbose cp -r "Cat Pictures" ~/Desktop A directory and everything inside it. -Verbose prints one line per file copied, which is how you see what actually happened.

Move, and rename

Move and rename are the same command. Give it a new name in the same directory and it renames; give it a different directory and it moves:

Rename
mv blue_document.txt yellow_document.txt
Move
mv yellow_document.txt ~/Documents
Move many
mv *_document.txt ~/Documents — every file matching the pattern.

Remove

Remove is rm in both shells. It does not use the recycle bin: the file is gone, and there is no undo.

JobPowerShellBash
Remove a filerm text1.txt rm text1.txt
Remove a file the system is protective about rm important_system_file -Force —
Remove a directory and its contents rm misc_folder -Recurse rm -r misc_folder

The handout's tables also list rmdir in both columns. Reach for rm -r when there is anything inside the directory: that is the flag that takes the contents with it.

Read the path before you press Enter. Remove has no confirmation step and no recycle bin, and a relative path is only correct if you are where you think you are — which is why pwd first is not a beginner's habit. A delete that follows a wildcard deletes every match, including the ones you did not picture.

Reading a file without opening an editor

Four commands cover almost every time you need to see what is inside a file — and one of them stops you drowning the terminal.

cat dumps the file. That is fine for a short configuration file and useless for a thousand-line log, because it keeps writing until the end and the useful part scrolls off the top.

JobPowerShellBash
Show the whole filecat .\important_document.txt cat important_document.txt
Page through itmore .\large_document.txt less large_document.txt
First linescat fruits.txt -Head 10 head fruits.txt (10 by default)
Last linescat fruits.txt -Tail 10 tail fruits.txt (10 by default)

The pager: more and less

more and less hand the file to a separate program that shows one screenful at a time — so the keys are not shell keys any more:

more (Windows)
Enter advances one line, space advances one page, q quits back to the shell.
less (Linux)
Up and down arrows page, g jumps to the beginning, G to the end, /word searches, q quits.

Note the naming: more is the Windows pager, less is the Linux one. The joke is older than either of us — less is more, in that it can also scroll backwards.

When you do want an editor

nano on Linux and Notepad++ on Windows are the two this course names. Both are text editors: they change the file, they do not run it. Editing configuration in a terminal editor is the skill that makes a headless server usable, because there is no window to open.

Searching for text inside files

The command you reach for when you know something is in there and you do not know which file, or which line.

Searching is the one job where the two systems use genuinely different tools rather than two names for the same one.

JobPowerShellBash
Search one filesls cow farm_animals.txt grep cow farm_animals.txt
Search several filesSelect-String cow *.txt grep cow *_animals.txt
Search a directory tree by name ls 'C:\Program Files\' -Recurse -Filter —

sls is the alias for Select-String, and the two are interchangeable in the shell. The string you search for can be a word, part of a word, a phrase, or more — which is where regular expressions come in: a pattern language for selecting text rather than typing it out exactly.

The handout's example is incomplete: it stops at -Filter without a pattern, and the pattern is the part you supply — the extension or name you are looking for. -Recurse is what makes it descend into subdirectories; without it you have searched one folder.

Both tools print the matching line, not the matching file. That is the point: the answer to "where is it configured" is a line number in a file, and the line usually contains enough context to tell you whether you found the right one.

Three streams, and why they are numbered

Every process has an input, an output and a complaints department. Naming them is what makes redirection possible.

Every process on both systems takes input and produces output through I/O streams — input/output streams. There are three, and they are numbered, which is the detail that makes the syntax make sense:

StreamNumberWhat it carriesDefault destination
Standard in (stdin)0 The input the process readsYour keyboard
Standard out (stdout)1 The normal output — the answerThe screen
Standard error (stderr)2 Error messagesThe screen

The split between out and error is not fussiness. It means a program can produce its real answer on one stream and its warnings on another, so you can keep the answer and throw the warnings away — or send the warnings to a log while the answer goes to a file.

Everything in the next two sections is one idea: a stream has a number, and you can tell the shell where that numbered stream should go instead of the screen. > moves stream 1 to a file, 2> moves stream 2 to a file, and | moves stream 1 into another command.

Redirecting output into a file

Four operators: replace, append, errors, and input. The difference between the first two is the difference between a log and a lesson you only learn once.

OperatorWhat it doesExample
> Redirects stdout to a file. If the file exists it is overwritten; if it does not, it is created. echo woof > dog.txt
>> Appends stdout to the file instead of overwriting it. echo woof >> dog.txt
2> Redirects stderr — the error stream, stream number 2 — to a file. rm secure_file 2> errors.txt
< Takes stdin from a file instead of the keyboard (the Linux form this course teaches). cat < file_input.txt

The black hole

Both systems have a destination for output you do not want:

Windows
$null — rm secure_file 2> $null throws the errors away.
Linux
/dev/null — less /var/log/syslog 2> /dev/null does the same. It is a real device file, and the reason it is a character device is that it swallows data character by character like everything else in /dev.
> overwrites without asking. Using a single arrow where you meant a double is how yesterday's output disappears — including when "the output" is a config file you were only meant to add a line to. Redirect into a new file when you are unsure, then compare.

Pipes: one command's output as the next one's input

The pipe is what turns a list of small commands into a line that does something none of them could do alone.

The pipe operator, |, sends the output of the command on its left into the input of the command on its right. Read it as "and then".

PowerShellBashWhat the line does
cat words.txt | Select-String st ls -la /etc | grep bluetooth Take the first command's output, and show only the lines that contain the string.
cat words.txt | Select-String st > st_words.txt ls -la /etc | grep bluetooth > bt.txt A pipe followed by a redirect: filter, then save the result.

Two operators on one line is normal, and the order is the whole program: produce → filter → save. Each piece does one job, and each piece is tested by the next one being empty or not.

Why this is the most useful idea in the module: you do not need a command that lists "the bluetooth files in /etc". You need one command that lists everything and one that picks lines, joined by a pipe. That is how a small set of tools covers an unbounded set of questions — and why scripting is possible at all.

Environment variables, and why PATH matters

The one setting that explains why a command works in one shell and not another.

An environment variable is a named value the operating system gives to every process — a machine or session setting a program can read without being told it on the command line.

The one worth knowing by name is PATH: the list of directories the shell searches when you type a command. When you type ls, the shell does not search the whole disk — it walks the directories in PATH in order and runs the first match.

The symptom
"Command not found" for a tool you know is installed. You are not in the wrong directory; the tool's directory is not in the list the shell searches.
The fix
Add the tool's directory to PATH, or run it by its full path so the shell does not need to search at all.
The trap
Two tools with the same name in two directories on PATH. The first one wins, silently, and the version you get depends on the order of the list.

This is the same class of confusion as an alias: the word you typed is being resolved to something else before it runs. Get-Alias answers "what is this name pointing at" inside PowerShell; PATH is the equivalent question one level down, across the whole system.
